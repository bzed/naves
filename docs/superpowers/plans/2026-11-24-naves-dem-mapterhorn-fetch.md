# Naves dem fetch (Mapterhorn bare-earth DEM) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `naves dem fetch` downloads the bare-earth height model (DTM) for a project's map window from Mapterhorn's Terrarium tiles, writes it as one Float32 EPSG:4326 GeoTIFF that today's `sources.dem` reads unchanged, and lists it in `naves.toml`.

**Architecture:** One new module `naves-export/src/dem_fetch.rs`, a Float32 sibling of the existing GeoTIFF writer, and a thin CLI subcommand, all mapping the proven pattern of `imagery_fetch.rs` (ureq agent, injectable source, retries, atomic writes, toml upsert). `naves build` is untouched: it reads the produced GeoTIFF with the existing `dem.rs` reader.

**Tech Stack:** Rust (workspace, edition 2024), `image` 0.25 with the `webp` feature (pure-Rust lossless VP8L decode — Mapterhorn tiles are lossless), `ureq` 3.5.1 with rustls, `tiff` 0.11 with deflate, rayon.

**Spec:** `docs/research/2026-11-23-1m-dem-sources.md` (§2 the service, §4 ingest path 1, §6 risks) and the spike answers `.superpowers/sdd/2026-11-24-naves-dem-mapterhorn-fetch/spike/answers.md` (measured values, verdict). Both travel with this plan. All numbers below are measured, not estimated.

## Review Focus

1. **Server answers that are not tiles** (error pages, wrong dimensions, oversize): `terrarium` rejects anything that is not 512×512 RGB; `RealTiles` caps answers at `MAX_TILE_BYTES`; both surface as `FetchError` naming the tile, never a panic or a silent zero (Task 3, Task 5).
2. **Window a tile source cannot cover** (a 404 at every zoom, or a `--zoom` above native everywhere): `resample` errors, naming the first missing tile id and its position, instead of writing a hole that `build_heightmap` only reports at vertex level later (Tasks 4, 5).
3. **Maps bigger than `dem.rs` accepts** (extent above ~20.5 km at 2.5 m/px): the pixel size grows with the extent (`pixel_m = max(requested, (extent + 2·MARGIN_M)/8192.0)`), and the `MAX_PIXELS`/`MAX_SIDE_PX` guards error clearly before anything is written (Task 4, Task 5).
4. **404 at native zoom is a fallback, not a failure** (macro-tile zoom borders, GLO-only regions): per-tile parent fallback down to `Z_MIN`, and a query whose bilinear quad touches a missing neighbour falls back as a whole to the next coarser zoom (Tasks 3, 5).
5. **Re-runs must not hammer the server or double-list the file**: cached tiles are never re-requested (counted in tests), and the `sources.dem` upsert never duplicates the entry (Task 5).

```rust
/// Decodes one 512x512 Terrarium tile (webp bytes) to `TILE_PX*TILE_PX` heights, row 0 north.
pub fn terrarium(bytes: &[u8]) -> Result<Vec<f32>, FetchError>
/// Decoded tiles by (z, x, y), sampling with per-tile parent fallback.
pub struct TilePyramid { /* fields private */ }
impl TilePyramid {
    pub fn insert(&mut self, z: u8, x: u32, y: u32, bytes: &[u8]) -> Result<(), FetchError>
    /// Bilinear height at a position; None if no cached tile, at any zoom, covers it.
    pub fn sample(&self, lat: f64, lon: f64, zoom_max: u8) -> Option<f64>

```
- Pin behaviour for `sample`: for `z` from `zoom_max` down to `Z_MIN`: compute `world_px`, take the bilinear quad of neighbouring pixels at `z`; if **all four** pixels are cached, interpolate and return; if any is missing, continue at the next coarser zoom. `None` only when no zoom serves the point.

### Task 4: Resample the window and guard the raster size

**Files:**
- Modify: `crates/naves-export/src/dem_fetch.rs`
- Test: `crates/naves-export/tests/dem_fetch.rs`

**Interfaces:**
- Consumes: Task 1 `DemMosaic`, Task 3 `TilePyramid.sample`.
- Produces:

```rust
/// Target pixel in metres for a project, honouring `--pixel-m` as a floor: bigger maps grow it.
pub fn pixel_m(project: &Project, requested: Option<f64>) -> f64
/// Samples `pyramid` at the centre of every target pixel of `window` …
pub fn resample(pyramid: &TilePyramid, window: &GeoWindow, center_lat: f64, pixel_m: f64, zoom_max: u8)
    -> Result<DemMosaic, FetchError> // rayon over rows, `FetchError::Other` naming the first missing tile

- Grid: `pixel_x = pixel_m/(111320·cos center_lat)` in degrees, `pixel_y = pixel_m/111132`; `width = ceil((east−west)/pixel_x)`, `height = ceil((north−south)/pixel_y)`; sample at pixel centres (`west + (c+0.5)·pixel_x`); bounds error if `width·height > MAX_PIXELS` or a side `> MAX_SIDE_PX`.

- [ ] **Step 1: Failing tests**: (a) a pyramid from one synthetic linear ramp tile (constant gradient in lat and lon) resamples to a 4×3 mosaic whose corners match the analytic heights at those centres within `1e-6` (the raster is small and exact values test the degree-space math); (b) `pixel_m`: default 2.5; a 24.5 km-extent project gets `3.0`; an extent that would exceed `MAX_PIXELS` errors from `resample`.
- [ ] **Step 2: verify failures → Step 3: implement** (rows via `rayon`, fixed order, deterministic) → **Step 4: PASS** → **Step 5: commit** `feat: window resampling with raster size guards`.

/// Where tiles come from. `Ok(None)` is a 404 — absent at this zoom.
pub trait TileGet: Sync {
    fn tile(&self, z: u8, x: u32, y: u32) -> Result<Option<Vec<u8>>, FetchError>;
}

/// Production source: ureq agent mirroring `RealHttp` (https only, UA `naves/<version>`,
/// timeouts), 404 -> `Ok(None)`, other failures through `with_tries`.
pub struct RealTiles { /* agent */ }
impl RealTiles { pub fn new() -> RealTiles }

pub struct DemFetchRequest { pub zoom: Option<u8>, pub pixel_m: Option<f64> } // derives Default; None means "discover"/"2.5 m"

/// Fetches the bare-earth DEM of a project into `dem/mapterhorn_dtm.tif` and lists it in `naves.toml`.
/// Sequence: read cached tiles -> fetch missing (TILE_JOBS parallel via a rayon pool) -> resample
/// -> write_dem atomically -> attribution sidecar -> upsert `sources.dem` -> `project.save`.
pub fn fetch_dem(project_dir: &Path, request: &DemFetchRequest, tiles: &dyn TileGet,
                 note: &mut dyn FnMut(&str)) -> Result<Vec<PathBuf>, FetchError>
```

- Consumes: Task 2's `fetch_window`/`tile_range`, Task 3's `TilePyramid::insert`, Task 4's `pixel_m`/`resample`, Task 1's `write_dem`, `imagery_fetch`'s `FetchError` and the now-`pub(crate)` `with_tries`, `project.save` from `naves-core`.
- Zoom discovery when `request.zoom` is `None`: probe the 4 window corners and the centre, `Z_MAX` down to `Z_MIN`; the highest `z` at which all five exist is the target zoom (cache hits count as exists). Per tile: fetch at the target zoom; on `None` walk down to `Z_MIN`; a tile missing at every zoom is the Task-4/`resample` error path.

## Notes for the implementer

- `naves build`, `dem.rs` and the height pipeline are **untouched** by this plan; if a task seems to need them, stop and re-read the spec — the point of path 1 is that the build reads an ordinary GeoTIFF.
- The spike's scratch (fetch script, repack, both reports, hillshade image) lives in `/var/tmp/naves-mapterhorn-spike/` while this machine stays up; it is evidence, not source.
- The measure of success is the recorded report deltas in the spike answers: road findings broadly down, `earthworks_capped` up because real gorge walls replace the DSM's smoothness. That regression is expected, disclosed in the manual, and **not** to be hidden by pre-smoothing the raster.
